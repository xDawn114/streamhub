# 跨进程编码能力缓存

本机177源码已接入正式`Sunshine.build.json`及完整原生补丁，版本为`streamhub.4.trace1.persist2`。原生开关默认关闭，产品生成的profile启用；旧profile只在停止引擎后补缺失项，保留显式关闭和既有计划。电脑和平板最近实装仍176，本次构建不等于安装或性能验收。

`streamhub_persist_probe = enabled`只允许在Windows、SDR探测计划、当前进程尚无编码器结果时读取该profile的`state.json.probe-cache-v1`。缓存包含backend名称、能力位、模式、时间及SHA256环境指纹，不包含原生对象、凭据或配置正文。EXE、配置、命令行、GPU/驱动/输出环境及计划不匹配，记录损坏、超过4096字节或满7天时重新探测。命中仍创建捕获/编码对象，以H.264 1080p60样本验证首IDR；其他codec能力来自同环境历史结果，未全部重新验证。真实重验失败和运行时编码失败均失效回退，不改变活动串流配置。

安装器只观察既有主屏服务启动，最多等待30秒。原生`serverinfo`报告`streamhub_probe_cache=ready`才算预热完成；健康但无可用缓存不能冒充完成。暂停接收、显式关闭主屏、活动会话、缓存不可用或超时均跳过/延后，不启动副屏或媒体会话，不更改显示拓扑。

接入依据是[阶段128](../../../../reports/stage128.md)固定工具链的交替对照：缓存命中冷连中位3989 ms，5次中1次超过5000 ms；首次无记录7426 ms、失效回退5197/5249 ms。当轮按旧判据未通过，未纳入175。这里不再使用阶段127不同编译环境的历史百分比判断回归，也不把历史4秒写成本机177已达标。

`persistent-probe.patch`相对`streamhub.4.trace1.locked1`含缓存及只读就绪状态；正式完整补丁为上级目录的`sunshine-63d35f7.patch`。完整1503项源文件回放核对及本轮构建见[阶段132](../../../../reports/stage132.md)。后续只在具体性能改动的同日交替对照或交付验收时采样，按[首帧验收规则](../../docs/首帧验收规则.md)记录中位与最慢值。

`PersistedProbeChecks.cpp`检查记录格式与能力边界，`PersistedProbeIoChecks.cpp`调用生产Windows缓存读写/指纹/恢复函数，捕获与编码用回调替身，不接触显卡或实装。后者发现真实重验失败时ifstream句柄未关闭会阻止Windows删除记录；`persist2`已在重验前关闭句柄，失败路径验证缓存确实删除、能力位恢复。

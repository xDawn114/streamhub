# 安装载荷与升级启动（本机候选）

阶段122只改本机源码，未产生新发行版本、未安装。现有三端实装证据仍为0.8.26/168。

## 安装载荷

安装根目录仍采用 `isolated-v2`：主屏和副屏各自的EXE、资源、配置与显示恢复状态独立。载荷中只省略两套引擎分发目录内大小及SHA256均相同的不可变文件，以 `.streamhub-payload-map.json` 指向已保存的原件；解包时复制成独立文件，不建立硬链接。不对配置、凭据或运行状态做别名。

打包器先检查完整文件清单及每一份原件，再省略重复内容。安装器与静态资源检查器共用解析规则，拒绝路径穿越、重复或未列出的文件、目录链接、缺失或循环别名、别名内容身份不同。安装器还按原清单核对还原后的大小、哈希和固定引擎身份；旧版无映射的载荷仍可读取。

用168的294个原文件、同一.NET Optimal压缩做对照：载荷344,828,829→311,636,090字节，减少33,192,739字节（9.63%）；135份重复资源合计97,265,569未压缩字节。此数不代表新安装器的最终大小，也不减少安装后的磁盘占用。

已校验文件的只读锁转交给专用STA启动线程。主界面最多前台等待45秒；超时后继续观察原启动请求，保留文件锁并阻止重复启动。授权返回后释放文件锁，记录进程ID，跟踪安装器阶段；安装等待超过5分钟会给出状态提示，继续观察，不强杀进程，也不把超时当失败后再拉起一次。界面可正常响应；关闭界面不会被写成安装成功。

每次尝试使用随机追踪ID。用户缓存中的 `updates/install-attempt.json` 保存请求、进程创建、UAC取消或退出码；管理员安装器取得安装锁后，才保护日志目录并在 `C:\ProgramData\StreamHub\logs\install-<ID>.json` 和既有 `安装.log` 中写入入口计时、安装锁、资源验证、停服、备份、文件替换、重启、完成或失败。锁竞争和父进程等待超时由调用端退出码记录，新增入口追踪不在取得锁之前改ACL或账户归属。没有接受外部指定日志路径。

退出码16表示另一项安装占有锁，17表示恢复等待父进程超时。安装锁检查实际占用，兼容已存在但空闲的锁，以及进程异常退出后的遗留锁。安装器退出0和完成记录只表示安装器报告结束；重启后仍需按当前程序的真实构建号确认目标版本。

隔离检查不调用ShellExecute、不申请UAC、不启动正式安装器，不能据此宣称历史上的“没有弹窗”已在实机解决。下一次安装时需验证一次正常授权、一次取消和完整阶段记录。

# 首帧验收规则

2026-11-17起使用。旧报告保留原始样本和当时判据，不追溯改成通过。

只在判断具体性能改动效果时进行同日交替对照，或在交付前验收。普通界面、文案和未改动性能路径的轮次不重复冷5/热5；功能冒烟出画不计作性能样本。

冷连交付门为同一场景样本的**中位≤5000 ms、最慢≤5500 ms**。缓存命中、首次无记录、指纹失效和真实重验失败后的回退分别报告，保留所有慢样本，不把只命中的结果当作完整首次体验通过。热连保留10%退化线，但必须有同日、同机、同预设、同工具链并交替采集的对照；缺少对照时写“未评估”，不拿历史中位计算失败或加速比。

新装后的首次策略是利用接受连接时已有的主屏引擎启动，先完成一次有界预热。安装器最多等待30秒，读取引擎真实完成的缓存状态；暂停、显式关闭主屏、活动会话、无交互桌面、缓存不可写或超时则跳过/延后并记录，不改变用户接收连接的选择。延后后首次连接仍可能发生完整探测，不能宣称所有安装状态都消除冷探测。

端到端首帧取自产品诊断。客户端host-ready、RTSP、解码配置、关键帧到达与原生探测、编码初始化、提交至IDR区间分开报告，禁止跨设备相减或把各段中位拼成一次会话。新的原生session匹配用于分段取证，不改变客户端首帧时钟。

相同原生二进制不代表整条链路未变：服务端、安卓及机器状态均可能影响结果。只在控制变量齐备时给出改动效果结论；其他数据只作为独立测量。

持久缓存只保存已验证的能力元数据。命中仍创建捕获/编码对象并实际验证，身份变化、记录损坏、超时或失败按正常探测回退。活动串流不得为补齐能力而提高编码、分辨率、HDR或色度；本轮不增加出画后的后台能力升级。

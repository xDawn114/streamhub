当前为 internal 渠道，不是 stable 发布承诺。签名清单有效期为 14 天；后续发布或续期要重新签署。过期清单会被拒绝。Pages 实际返回 `Cache-Control: max-age=600` 和 ETag，不能等同于自管服务器的 no-store 配置；客户端发 no-cache 请求。本轮分别验证线上完整字节和真实升级；没有放宽 `Test-UpdatePublication.ps1 -Online` 要求清单 no-cache/no-store/max-age=0 的严格门槛，当前 Pages 站点不满足该缓存门槛，仍是后续正式托管的待办。

## 准备发布

先核对源码快照、五项交付文件、版本和 SHA256：

```powershell
./scripts/Prepare-UpdatePublication.ps1 -Mode Plan -SourceRoot <完整源码> -CandidateRoot <双端候选根> -OutputRoot <新交付目录>
```

真实资源就绪后运行 Stage，传入外部清单私钥、更新说明和原 Android 证书指纹。当前显式使用 `-WindowsQueryOnly -AndroidOnlyHosting`；`-PackageBaseUrl https://xdawn114.github.io/streamhub/packages` 保留项目路径。这样 Windows 包只在本机核对，`hosted=false`，绝不作为可下载的受信包发布。

`Test-UpdatePublication.ps1` 重验两份清单、实际包字节、版本和同源约束。`readyToUpload=true` 只表示本机静态内容完整；线上字节与真实客户端升级另记，不回写成已验。

## 部署与回退

先上传不可变安装包，再替换清单；不可覆盖已有哈希路径。仓库以 `.gitattributes` 禁止 JSON/APK 换行转换，避免清单字节与本机记录不一致。部署后禁止跳转地读取两个 feed 和 hosted=true 的完整安装包，核对 HTTP 200、字节数和 SHA256。

服务器可以恢复仍有效的已审清单，但客户端不接受降版。已升级用户需要更高构建码修复包。保留先前已发布哈希路径，不把旧包当临时文件删除。源码与构建来源必须随相应版本固定。

Windows 获得可信签名服务、证书、时间戳和真实发布者指纹后，重新配置并构建带白名单的引导版；再单独验下载、Authenticode 信任链与安装。目前只验了真实清单查询和下载前拒绝，尚未执行真实发布者验签、线上 Windows 升级或签名后的 SmartScreen 行为。

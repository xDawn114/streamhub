# CodeQL 告警逐项定性

检查点：公开仓库切换到 `main` 后、同步本轮产品源码之前。API 共有 19 条历史告警，其中 14 条仍为 open、5 条 fixed。下面保留告警编号，便于追踪后续重扫结果。未在 GitHub 自动 dismiss；人工判断不等于分析器已关闭。

| 编号 | 规则 / 位置 | 定性与依据 | 后续 |
| --- | --- | --- | --- |
| 1 | C# user-controlled-bypass / info 路由 | 认证边界需持续验证。路由分派会读取请求路径，但进入分派前已有统一令牌、来源与设备权限检查，路径判断本身不授予权限 | 保留未绑定、撤销设备和跨权限的实际 API 回归；不能只看这一条条件判断 |
| 2 | 同规则 / receivers 路由 | 同一认证边界；接收设备身份另由设备凭据与 clientId 对应关系核对 | 持续覆盖伪造 clientId、撤销设备与跨设备操作 |
| 3 | 同规则 / prepare 路由 | 同一认证边界；准备操作另核对绑定授权、模式权限和租约 | 持续覆盖无权主屏、副屏、不同租约及暂停状态 |
| 4 | 同规则 / jobs 路由 | 同一认证边界；`AuthorizeJob` 验证任务归属，并非获知 jobId 即能访问 | 持续覆盖跨设备读取与取消任务 |
| 5 | Java compound assignment / Game 角度 | 可维护性问题；短整型角度在归一化时发生隐式收窄，当前 0–359 度范围可容纳 | 单独改为显式整数归一化并测笔输入边界；不宣称已修 |
| 6 | 同规则 / TrackpadContext | 可维护性及输入边界问题；浮点增量累加到整数时会丢小数 | 保留为输入精度工作项，需设备回归，不能直接当作无影响 |
| 7 | 同规则 / TrackpadContext | 与 6 号为另一坐标轴，同样存在隐式截断 | 同上 |
| 8 | Java SSRF / HubControlClient | 受约束的主动连接能力。应用需要访问用户绑定电脑；地址受 IPv4/通道策略约束，且在携带凭据前核对固定证书身份 | 保持错误地址、不匹配指纹、禁止重定向等回归；不能套用只允许公网地址的 Web 服务策略 |
| 10 | Java TOCTOU / HubSessionLease | 分析器对并发模型的覆盖有限。当前首帧与视频代次更新均同步，并核对当前 trace、关闭标记及只记录一次；161 已新增旧代次回调测试 | 保留代次/关闭竞态测试，仍不把所有并发路径视为已证明安全 |
| 11 | Java weak crypto / PairingManager SHA-1 | 真实遗留兼容算法。旧 GameStream 协议路径保留 SHA-1；产品绑定和新媒体身份路径不依靠 SHA-1 作信任根 | 追踪旧主机兼容的实际使用范围，不能静默改协议或宣称全部采用 SHA-256 |
| 12 | Java weak crypto / HubUpdatePolicy | 有约束的兼容别名：`SHA256withRSA/PSS` 是 Android provider 名称回退；两条路径均显式要求 RSA ≥3072、SHA-256、MGF1-SHA256 和 32 字节盐 | 继续在真实 Android provider 上验签；名称回退不是 SHA-1 回退 |
| 14 | Android sensitive-text / HubActivity | 需要人工复核的隐私项：网络账号和地址默认遮盖，明确点按可显示；身份授权 URL 由用户复制/打开 | 不展示令牌/私钥，保留遮盖默认值及取消授权检查；不能只因文字控件可见就判已无风险 |
| 15 | Android arbitrary-apk-installation / HubUpdates | 产品必需且受信任链约束的安装入口。安装前重新检查签名清单、版本、大小、SHA-256、包名和原签名者；最后由系统安装器确认 | 本轮执行真实引导版→新版更新；确认可安装不代表 Windows 已签名 |
| 19 | Java log-injection / LimeLog | 分析器未识别自定义净化。日志包装器将 CR/LF、NEL、Unicode 行/段分隔符替换为空格 | 保留净化回归，不输出绑定码、账号令牌或私钥；不将所有日志内容一概视为无敏感信息 |

5 条 fixed 历史告警：9（锁释放）、13（WebView 内容访问）、16（旧日志注入路径）、17（WebView JavaScript）、18（SeekBar 算术边界）。是否持续 fixed 以新提交的分析结果为准。

覆盖边界：当前工作流分析 Windows 自有 C# 与 Android Java。C++ Sunshine、JNI、Go、AAR 内部及第三方 exe/驱动不在这 14 条定性表的覆盖内；配置存在、编译成功或零新增告警都不等于完整安全审计。

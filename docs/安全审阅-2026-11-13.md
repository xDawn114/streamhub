## 阶段97只读观察（以下为整改前历史）

2026-11-13。本次根据用户提供的安全分析，只读核对本机防火墙和当前产品源码。没有进行渗透测试、模糊测试、独立安全审计或生产更新验收；下列结论不能代表不存在漏洞。本轮不修改防火墙、系统网络类别或已有绑定，避免打断正在使用的异地连接。

## 主要结论

公开源码会降低研究代码的成本，也让修复和外部审阅更容易。源码本身不包含每台设备运行时生成的证书私钥、绑定 token 或用户串流数据。获知协议和算法不等于取得授权；真正需要防守的是凭据泄漏、认证与授权漏洞、网络暴露和构建发布链。开源与闭源都需要这些控制。

用户分析中的方向合理，但目前没有依据把控制 API、文件接口整体评级为低风险，也不能把当前更新器描述为正在接受未签名更新。

## 已核实的事实与修正

| 项目 | 本次证据 | 对原分析的修正 |
| --- | --- | --- |
| Windows 防火墙 | `installer/Deployment.cs` 为产品规则设置 `Profiles=7`；本机八条产品入站规则确实覆盖 Domain、Private、Public | 49199、发现与主/副屏媒体端口均需纳入网络暴露设计，并非只有 49199 |
| 当前网络 | 本机 WLAN 为 Public，Tailscale 接口为 Private | 直接把全部规则改为 Private/Domain 会改变当前可用连接；应拆分 LAN 与受信 VPN 的放行条件，验证后迁移 |
| LocalSubnet 与 100.64/10 | 规则按来源地址限制；41641/UDP 来源为 Any | LocalSubnet 会随接口网络变化；100.64/10 是地址范围，不是 Tailscale 身份证明；还需依靠隧道、tailnet ACL 与应用认证。41641 是外层传输入口，不等同于匿名远控授权 |
| 控制 API | TLS 1.2/1.3、客户端固定证书指纹、随机 32 字节 Bearer token、常量时间比较、匿名/已认证限流、连接数/读取超时 | 有保护措施，但这些措施不足以证明整个 API 低风险。8KB 是普通 JSON 控制请求上限，文件与剪贴板使用单独的边界 |
| 六位短码 | `LocalBindingRegistry`：3 分钟窗口、错误 5 次失效、正确兑换消耗短码、电脑人工确认、nonce 校验与一次交付 | 短码不是单独的最终授权；电脑确认和首次指纹信任同样关键。发现广播不授予信任 |
| 长绑定码 | `ControlApiServer.LoadIdentity` 把服务证书指纹和持久 token 放入邀请码；token 来源于持久设备身份 | 长绑定码仍是秘密授权凭据，不能把短码的一次性语义套到它身上。当前 token 不是逐控制端独立签发；需设计单设备撤销、轮换和作用域 |
| 文件权限 | 共享 API 之外还有 `X-StreamHub-Client` / `X-StreamHub-Key` 校验，浏览根目录与删除权限分开 | 现有隔离有价值，但不能替代重解析点、竞态、路径边界和授权组合的攻击测试；文件接口不能仅按已有防护列表判低风险 |
| 更新配置 | `common/Updates/update-trust.json` 中 feed、公钥为空、发布者列表为空 | 当前尚未接入生产更新源，Windows 更新安装在缺失可信配置时拒绝执行；RSA 清单的实现与本地样例不等于生产公钥已经固定 |
| 更新验证代码 | `UpdatePolicy` 验 RSA-PSS 清单、渠道/版本/有效期与同源 HTTPS；`UpdateClient` 校验包大小/哈希、重新打开验证；`AuthenticodeVerifier` 检查可信签名及发布者 | 正确配置后的签名清单和哈希已阻止普通包替换。Windows 包当前未签名是首装来源、发布者信任及发布门的缺口，不等于现有更新器会接受任意替换包；签名本身也不证明软件无漏洞 |
| 特权服务 | `HostRuntime` 管道拒绝 Network SID，仅允许 SYSTEM、管理员与安装所有者，并在处理时核对调用身份；文件暂存使用调用者身份打开 | LocalSystem 提高漏洞后果，仍需审查命令授权、文件 ACL、提权边界和跨会话操作；有 ACL 不代表所有操作都安全 |
| CI 与开源材料 | 公开源码本地镜像有根级 `source-checks.yml`，本轮核对范围内未见根级 SECURITY.md、CodeQL 或 Dependabot 配置 | 上游子目录自带的 CodeQL/Dependabot 不等于本产品仓库已经启用；已有源码归档与哈希不能称为可复现构建 |
| 被控提示 | `SessionNotificationPolicy` 目前提供通用串流连接/退出托盘通知 | 仍未等同于持续显示经过认证的设备身份。建议补会话设备、实际连接通道、来源及可终止入口；不能仅信任客户端自报名称 |

## 建议落地顺序

1. **网络边界与授权生命周期。** LAN 默认仅 Private/Domain，Public 默认不开放 LAN 发现/控制/媒体；Tailscale 通路单独限定到受信接口/地址并保留 tailnet ACL。优先用独立设备凭据支持单设备撤销及轮换；兼容旧绑定需要明确迁移和恢复方案，不能静默使全部旧端失联。
2. **私密漏洞披露与依赖响应。** 增加 SECURITY.md，说明受支持版本、私密报告入口及不公开密钥/绑定码/复现数据；确认 GitHub Private vulnerability reporting 已实际开启后再写成可用。配置根级 CodeQL/依赖提醒，覆盖自有 C#、Java 与实际可扫描的原生源码。Sunshine/Tailscale/VDD 二进制和归档另外维护版本、来源与公告跟踪，依赖机器人不会自动覆盖它们。
3. **签名与发布链。** SignPath 当前申请已提交、尚待审核，Windows 包仍 NotSigned；Android 沿用已有发布签名。取得资格后接可信 CI、发布者固定、时间戳及人工发布批准，再配置生产 HTTPS feed、真实清单公钥与更新验收。源码和 CI 禁止包含签名私钥。
4. **有目标的安全测试。** 用隔离测试身份和临时目录对 JSON、认证前处理、超时/限流、短码状态机、文件路径/重解析点/竞态、剪贴板/分块大小、命名管道命令授权做 fuzz 和边界测试；不得对日常使用服务做破坏性测试。49199 不是唯一攻击面，还包括发现解析、串流/输入、更新解析及第三方引擎。
5. **构建可追溯与可复现。** 继续提供与包对应的源码、依赖版本、工具链、CI 构建记录和哈希；独立重建并解释差异后才能宣称可复现。哈希必须来自受信且独立验证的发布渠道，和包一起被替换的文本哈希不能认证来源。
6. **持续被控提示。** 显示已认证设备与会话状态，提供明显的断开/撤销入口，并确保隐私屏和安全桌面场景仍有恢复手段。标题栏冗余的“已就绪”可以移除，保留本机状态卡和既有托盘通知。

未授权或未执行的事项不得写为已经完成：本次没有收紧防火墙、轮换 token、申请新证书、启用 GitHub 安全功能、执行 fuzz 或上线更新源。

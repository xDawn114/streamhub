## 位置与导出

完整产品源码在独立 Git 仓库维护；同步使用独立工作树，不引入开发父仓库历史、私有报告或设备运行状态。

安全元数据的维护源是产品覆盖层中的 `SECURITY.md`、`.github/`、本文件、`第三方依赖与构建追溯.md` 及 `scripts/Export-ProductSource.ps1`。导出工具接收**已经合成的完整产品源码**，再覆盖本批维护的安全元数据，输出新的本机待审目录：

```powershell
./scripts/Export-ProductSource.ps1 -SourceRoot <完整整合源码> -OutputRoot <新的本机待审目录>
```

输出包含 `source/`、`product-source.zip`、逐文件 SHA-256 清单和导出记录。工具显式包含根级 `.github`，并回读 ZIP 核对全部字节；不使用可能漏掉隐藏文件的通配符压缩。它只复制产品白名单目录，不复制父仓库历史、设备报告、发布目录、构建缓存和常见私钥文件。符号链接/重解析点会被拒绝。文本另检查 PEM 私钥头、GitHub token、Tailscale auth/API/client key，发现时停止且不打印值；已知设备身份、Sunshine/Tailscale 状态、凭据/组网/文件暂存目录也会拒绝。

**不按 `.dll`、`.aar`、`.jar` 或 `.lib` 后缀一概排除构建输入。** `libtailscale.aar` 是 Product 范围的必需项；必要的二进制输入会进入逐文件哈希清单。二进制内容不由文本扫描完整分析，压缩包内部、任意格式的秘密、截图/个人文件和未识别运行状态仍需人工审阅；此工具不是穷尽保密或许可审计。邮箱是维护者明确指定的公开披露渠道，不把它误当成需删除的申请表资料。

`-Scope Windows` 用于现有 Windows 打包脚本的构建源码附件，包含安全文档与根级配置，但不声称包含完整 Android 构建材料。不能只拿 Windows 附件建立完整双端公开仓库。独立公开导出须使用默认 `Product` 范围，工具会检查 Android Gradle/JNI/组网材料是否齐全。

导出记录标记的是本机待审副本，不授权上传、授予新许可或发布，也不证明输入是当前候选或干净 Git 提交。导出前须确认输入版本与实际构建快照；构建追溯所需的提交/覆盖层差异另见[追溯说明](第三方依赖与构建追溯.md)。

## CodeQL 覆盖

| 配置 | 真实输入与范围 | 边界 |
| --- | --- | --- |
| `.github/workflows/codeql.yml` / `csharp.yml` | Windows runner 上实际编译 `host`、`service`、`installer`，包括它们链接的 `common` 代码；安装器采用无载荷的 Uninstaller 编译模式 | 不运行安装器、产品服务或业务测试；不分析第三方 exe/驱动。编译式提取不能靠 `paths-ignore` 排除已编译依赖 |
| 同工作流 / `java.yml` | `build-mode: none` 扫描 Android 主 Java 源码，包含自有 StreamHub 和修改的 Artemis/Moonlight 接收端 | 不启动 Gradle/NDK 或访问发布密钥；无构建分析的依赖解析与框架建模有限，不是 Android 编译验收。`java-kotlin` 是 CodeQL 语言标识，none 模式不覆盖 Kotlin、Go、AAR 或 JNI |
| `.github/codeql/cpp.yml` | 为完整修改版 Sunshine 的真实编译准备的独立配置 | **未接入自动工作流、未生成 C++ 数据库**。公开包只有补丁/锁文件时，不能伪报 C++ 扫描成功 |

三份配置均使用 `security-extended`。C++ 需要保留的完整 `Sunshine-streamhub-source.tar.gz`、`native/Sunshine.build.json` 对应的依赖、受支持的 CodeQL CLI/编译器和原生构建环境。先校验归档 SHA-256、解压后的 `modifiedSources`、子模块与外部依赖；不要对已修改源码再次应用补丁。数据库应捕获 `native/Build-Sunshine.ps1` 在全新构建目录里的实际编译。示意命令（路径由维护者在隔离构建环境提供）：

```powershell
codeql database create <新的数据库目录> --language=c-cpp --source-root=<完整修改版Sunshine源码> --codescanning-config=<产品根>/.github/codeql/cpp.yml --command='<含完整参数的pwsh原生构建命令>'
codeql database analyze <数据库目录> --format=sarif-latest --output=<本机结果.sarif> 'codeql/cpp-queries:codeql-suites/cpp-security-extended.qls'
```

这些命令本批没有执行。兼容性以实际 CodeQL/编译器版本为准；支持性或依赖不满足时应记录未覆盖，不降级为空库成功。手工编译可能提取上游和第三方源码；审阅结果时用 `modifiedSources` 关联自有改动，不能声称仅扫描了独占版权的 C++。Android JNI/C/ENet 和预编译库不因此自动获得覆盖。

## 托管启用边界

配置须进入独立仓库默认分支。私密漏洞举报和 Dependabot 安全修复已启用；Code scanning 的分析范围、上传权限和真实结果须分别按 Actions 与 Security 页面核对，不能仅根据 YAML 存在判断。

- 工作流仅用 `push`、`pull_request`、定时与手动触发；不使用 `pull_request_target`、发布凭据或 self-hosted runner。默认 token 只读，仅扫描 job 申请 `security-events: write` 和 `actions: read`。
- checkout 不保留认证凭据。checkout/setup-dotnet/upload-artifact 的三个新版本分别核对上游完整 SHA，并逐条通过 PR 检查后合并；CodeQL init/analyze 同时固定为 `33d7b85da1a04171e211befe2c739303b9a4c066`。2026-11-13 只读 `git ls-remote https://github.com/github/codeql-action.git refs/tags/v4 'refs/tags/v4^{}'` 返回 annotated tag 对象 `5895b2c9be147bc7f1c75ce72c5cb577febb1907`，其 peeled commit 为上述固定值；使用真实提交而不是 tag 对象。这仅核对官方远程引用，未执行 Action、验证其全部实现或开启托管扫描。
- fork PR 的 token 和 SARIF 上传受平台权限限制；若被拒绝，记录权限原因并在可信分支重跑，不改成以高权限执行外部 PR。
- `source-checks.yml` 保留编译和输入策略检查，并接入 `tests/control-boundary/ControlBoundaryChecks.csproj`、`tests/host-policy/HostPolicyChecks.csproj`、`tests/firewall/FirewallChecks.csproj` 与逐设备授权检查；这些检查使用内存或模拟对象，不访问真实桌面、密码、系统防火墙或运行服务。它不是签名/发布流水线，实际状态以当前提交的 Actions 为准。
- 不自动批准或合并 Dependabot PR。编译、协议兼容、签名、哈希锁及许可证变化仍需人工审阅。

## Dependabot 可实际覆盖的清单

| ecosystem / 根目录 | 当前可发现的声明 | 不覆盖 |
| --- | --- | --- |
| github-actions `/` | 根级 `.github/workflows/*.yml` 的 `uses:` 引用 | 托管服务是否开启、脚本中的 URL、runner 镜像和外部服务资格 |
| nuget `/host`、`/service`、`/installer` | 对应 `.csproj` 的 `PackageReference`：ServiceController、Pipes.AccessControl、ProtectedData | .NET SDK/运行时安全支持生命周期，安装包中 self-contained runtime 的真实版本 |
| gradle `/client/artemis-src` | `settings.gradle` 声明的 `app`，根/app `build.gradle` 的 AGP 和 Maven 依赖 | `files('libs/libtailscale.aar')` 的内容、vendored JNI、手工 ZIP/归档哈希；Gradle wrapper 另须人工跟踪 |

`client/network-core/upstream-go.mod` / `upstream-go.sum` 是上游构建记录，不是标准名称的可构建 Go 模块；不添加一个看似覆盖却找不到 `go.mod` 的 gomod 配置。源码快照也没有保留可更新的原生 Git submodule gitlink；不以 `git-submodules` 规则代替人工跟踪。当前其余自有 `.csproj` 没有 `PackageReference`；新增依赖或移动目录时应同步更新清单。

Dependabot 版本更新、漏洞告警与自动安全更新是不同的托管功能；存在 YAML 只代表准备了版本更新配置。第三方引擎和预编译库的跟踪、响应与构建记录见[第三方依赖与构建追溯](第三方依赖与构建追溯.md)。

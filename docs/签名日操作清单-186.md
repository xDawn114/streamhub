# 186 签名日操作清单

这份清单对应 0.8.44 / 186 的待签候选。它记录顺序和证据要求，不代表 SignPath 已批准，也不替代真实证书验证。

## 签名前

1. 冻结源码提交、候选目录、组件清单和构建结果；保存 SourceRevision 与所有 SHA256。
2. 在 GitHub Actions 的 Windows signing / check 先跑配置检查，确认组织、项目、策略、两个工件配置、令牌和发布者指纹都齐全。
3. 确认没有串流、文件传输或其他安装任务；准备回滚包、隔离 Windows 测试机和带信任根的引导安装包。
4. 运行：pwsh ./scripts/Start-SigningDayChecklist.ps1 -PendingReleaseRoot <待签候选目录> -SourceRevision <40位提交> -OutputRoot <新的检查单目录>

## 固定顺序

1. 从当前提交编译 我控制.exe、串流中心后台.exe、卸载串流中心.exe。
2. 第一次 SignPath 请求只签这三个自有程序；人工批准后校验 Authenticode、时间戳、证书指纹、版本和目录内容。
3. 用这三个已签程序重新生成载荷、组件清单和安装器；载荷哈希发生变化时，旧安装器作废。
4. 第二次 SignPath 请求只签新生成的安装器；批准后校验外层签名，并静态提取载荷确认三份内层程序仍有正确签名。
5. 用 Complete-WindowsSigning.ps1 生成最终签名目录，保存两次请求 ID、源码提交、安装器哈希和载荷清单哈希。

## 真机验收

1. 在隔离 Windows 机器安装带新发布者信任根的引导包，确认程序启动、服务启动和原设置保留。
2. 用更高构建码的签名候选执行一次应用内升级，记录清单读取、下载、大小/哈希/发布者校验、安装回执、新版本进程和设置保留。
3. 另测取消、下载失败和回滚；任何一步失败都不能把签名日记为通过。
4. 最后再更新公开源码标签、发布包和在线清单。签名完成前不启用 Windows 下载更新。

## 当前结论

- 当前没有真实 SignPath 证书签名记录，签名日只能按上述顺序执行。
- 当前发布者白名单为空，Windows 应用内更新保持阻断。
- 不能用未签名包、手动覆盖安装或催办回执替代真实签名和在线升级证据。
